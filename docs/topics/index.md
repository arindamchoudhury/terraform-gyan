- **refactoring** — currently from: TID Ch2 §2.9 + **TID Ch9 §9.5–§9.6** (internal vs external refactoring with the inputs/outputs test for which is which, tests as the detector, `moved` blocks as permanently public, the parallel-change pattern for renaming a variable, and batching breaking changes onto a provider major) + **TID Ch6 §6.5** (`moved`/`removed` blocks, `state rm`/`replace-provider`, hand-edit last-resort) + [[tf-state-refactor]] (the **cross-configuration** case: when to split, how to group, the `removed`+`import` migration recommended over legacy `state mv -state/-state-out`, empty plans on both sides as the proof); full treatment is TID Ch9. **TUR Ch5** supplies the *motivation* the others assume: renaming a variable, a resource identifier, or a module — or adding `count`/`for_each` to something that lacked it — reads to Terraform as delete-and-create, and if the resource is an ALB or a security group that means an outage. Its argument for `moved` blocks over `terraform state mv` is about other people: a CLI step has to be remembered by every team that consumes the module, a `moved` block travels with the code.
- **opentofu-divergence** — currently from: [[ot-provider-for-each]], [[ot-early-eval-backend]], [[ot-exclude-flag]], [[ot-dynamic-prevent-destroy]] + **TID Ch10 §10.7** (the compatibility report — every book example ran unchanged on both engines — and `.tofu` files as the per-file, one-directional shadowing mechanism that lets one module exploit an OpenTofu-only feature while staying Terraform-compatible). Two corrections found while capturing it: provider functions are OpenTofu **1.7**, not 1.8, and the `winrm` connection type is deprecated on OpenTofu 1.12 with removal scheduled for 1.13, with no Terraform equivalent move.
- **provisioners-and-escape-hatches** — currently from: **TID Ch10 §10.3–§10.5** (`connection` placement and `self`, the three `remote-exec` script arguments, `when = destroy` and its `prevent_destroy`-shaped trap, `on_failure` and taint-on-failure, `terraform_data` as a provisioner host, and the purpose→alternative table that ends at immutable images and Cloud-Init; then the `external` provider's stdin/stdout contract and the `local` provider's data sources, resources and `direxists`) + [[pyinfra]] (the handoff framing — `terraform output -json` as the seam, and outputs-vs-state as a blast-radius choice). Two sources — promotable; feeds **A1**. It also still teaches `null_resource`, superseded by `terraform_data` with a supported `moved` path since Terraform 1.9.
- **checks-and-conditions** — currently from: **TID Ch10 §10.6** (the blocking/warning split, `self` under `count`/`for_each`, why preconditions existed before cross-variable `validation`, and scoped data sources with the first-plan `depends_on` trap) + [[tf-conditionals]] (`can()`, `self` in a postcondition, `each`/`count` in expanded-block conditions).
